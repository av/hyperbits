title: CLI
description: Search, fetch, and add hyperbits from the terminal

The `hyperbits` binary ships with the npm package.

```bash
npx @av/hyperbits find [query] [--tag <tag>] [--limit <n>] [--json]
npx @av/hyperbits fetch <id-or-name> [--json]
npx @av/hyperbits add <name...> [--into compositions/] [--set <id=value>] [--json]
npx @av/hyperbits mcp
```

## find

Search the published catalog by visual goal and tags.

```bash
npx @av/hyperbits find "gradient background"
npx @av/hyperbits find "text reveal" --tag text --limit 5
npx @av/hyperbits find --tag particles --json
```

`--tag` is repeatable. Comma-separated values are accepted. Each result lists its variable ids (`Variables: text, color, background`), so you can pick a bit that exposes the knobs your design system needs. `--json` prints a stable object with a `results` array; each result carries the full `variables` declarations.

## fetch

Print one bit record, including its variables, HTML source, helper script tag, and the embed snippet.

```bash
npx @av/hyperbits fetch fade-in
npx @av/hyperbits fetch fade-in --json
```

The human output lists the variables before the source:

```text
   Variables (id, type, default, label):
     text        string  "Hello World"  Text
     color       color   #fcc192        Text color
     background  color   #100f0f        Background
   Override per instance: data-variable-values='{"text":"Hello World","color":"#fcc192","background":"#100f0f"}'
```

`--json` returns the same list as `bit.variables`: `{ id, type, label, default }` per entry, in declaration order.

The identifier can be the bit id (`fade-in`) or the exact display name (`Fade In`). Unknown names print close matches (`Did you mean: fade-in?`).

## add

Write one or more bits into a HyperFrames project and print the snippets to embed them.

```bash
npx @av/hyperbits add fade-in
npx @av/hyperbits add fade-in glitch-in --into compositions/
```

`add` writes `compositions/<id>.html` per bit and copies the helper bundle `hyperbits.iife.js` next to them. After each embed snippet it prints a ready-to-edit `data-variable-values` example built from the bit's declared variables:

```html
<div data-composition-src="compositions/fade-in.html"></div>
<div data-composition-src="compositions/fade-in.html" data-variable-values='{"text":"Hello World","color":"#fcc192","background":"#100f0f"}'></div>
```

Values in `data-variable-values` override the declared defaults for that one embed. Leave out the ids you do not change.

### Theme on install with --set

`--set id=value` writes a new default into the installed copy, so every embed of that file starts from your palette without `data-variable-values`. It is repeatable and applies to every bit in the call that declares the id:

```bash
npx @av/hyperbits add fade-in glitch-in staggered-fade-in --into compositions/ \
  --set background=#0b1020 --set color=#e8ecff --set text="Launch day"
```

```text
Wrote compositions/fade-in.html
  Set background=#0b1020
  Set color=#e8ecff
  Set text=Launch day
...
Wrote compositions/staggered-fade-in.html
  Set background=#0b1020
  Set color=#e8ecff
  Skipped --set text: staggered-fade-in has no "text" variable
```

- Values are checked against the variable type: `color` takes any CSS color (`#rgb`, `#rrggbb`, `rgb()`, `hsl()`, `oklch()`, named colors), `number` a finite number, `boolean` `true` or `false`, `string` anything.
- Bits also repeat a color default as a literal in CSS and markup (`html, body`, `#bg`, `:root` tokens). The literal shows when the embed outlasts the bit's own clips, so `--set` rewrites those copies as well. If two variables of a bit share the same default (for example `color` and `background` both `#000000` in `ken-burns`), the literals are left alone and `add` prints a warning; the variable itself still applies.
- Nothing is written when a bit is unknown (exit 3), a `--set` is malformed or invalid, or no bit in the call declares the id (exit 2).

`--json` returns `{ "added": { ... } }` for one bit and `{ "added": [ ... ] }` for several. With `--set`, each record also has `set` (applied values), `skipped` (ids the bit does not declare) and, when needed, `warnings`.

## mcp

Start the hyperbits MCP server on stdio. See the [MCP page](/docs/mcp).

## hyperframes add

`npx hyperframes add` does not take a registry URL. Point a project at this catalog by setting `registry` in `hyperframes.json` to the docs site origin (the host of `/registry.json` and `/blocks/<name>/registry-item.json`), then:

```bash
npx hyperframes add fade-in
```

`hyperbits add` is the guaranteed install path. The HyperFrames registry is an extra path, not a substitute.
